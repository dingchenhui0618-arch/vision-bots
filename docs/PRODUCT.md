# 深层媒体工作室 · 产品定义

> 一句话：**DS-Bot 的编排骨架，垂类化到自媒体内容生产。** 一个主 bot 带一队小 bot，在一张群聊里把素材做成能直接发布的片子。

## 1. 产品是什么

不是"功能列表"，不是"模板市场"，是**一支常驻的创作团队**。

- 用户打开产品，看到的是**一个群**，不是一个按钮面板。
- 群里有一个**主 bot（制片人）**和若干**小 bot**。
- 用户说一句需求，主 bot 对齐目标、拆阶段、派活、验收。
- 小 bot 各自干活，在群里报进度、发中间产物、互相 @。
- 用户随时插话、改主意、叫停、退货。
- **skill 不是产品形态**，是每个小 bot 的内功：它决定这个 bot 做出来的东西够不够折光水准。用户看不见，也不需要知道。

## 2. 编排模型（照搬 DS-Bot）

| 概念 | 在本产品里 |
|---|---|
| Main bot | **制片人**。唯一的门面。管其他 bot 的增删改，接需求、定 Goal、拆阶段、验收、交付。不亲自剪片。 |
| Bot | 一个长驻身份：人设 + 模型 + 记忆 + 工作文件夹 + 权限 + 内置 skill 包 + 模板库 |
| 群聊 | 一个项目现场。有独立记忆和独立工作文件夹，群外的 bot 看不到 |
| Goal | 一条片。制片人先和用户对齐完成标准，再拆阶段 |
| 派活 | 任何 bot 都能 @ 另一个 bot；接活的自己做，做完把结果发回群里 |
| 会话 | 每个 bot 在自己的 chat 里一段会话，每个群一段会话；上下文满了由 context steward 压缩或写交接笔记开新段，用户始终只看到一个群 |
| 记忆 | bot 记住用户的偏好（语速、字幕样式、BGM 习惯、禁用词），下次直接应用 |

## 3. 小 bot 花名册（第一批）

每个小 bot 都自带一整套 skill 和模板，对外只说人话。

### 3.1 选题（主编）
- 干什么：定选题、定角度、写口播稿
- 内功：选题配比、人类化写作门禁（去 AI 味）、三平台标题结构
- 模板：观点强钩 / 故事反差 / 教程三步 / 数据拆解 / 热点跟进
- 产出：选题卡、口播稿、一句话钩子

### 3.2 剪辑
- 干什么：转写、逐字对齐、气口压缩、跳切、变速、分段
- 内功：脚本为准的对齐、静音感知跳切、变速保持音高
- 模板：快节奏 1.3× / 沉稳 1.1× / 保留呼吸 / 全速不剪
- 产出：`timeline.json`、粗剪（低成本可预览）

### 3.3 包装
- 干什么：动效、字幕卡、花字、封面、转场
- 内功：逐帧渲染引擎、字幕卡规则、封面版式与安全区
- 模板：光轨高密度 / 极简扫光 / PPT 底座 / 纯字幕
- 产出：`scene.json`、成片渲染、封面

### 3.4 声音
- 干什么：响度匹配、BGM、音效、节拍对齐
- 内功：语音式归一、母带限幅、音效只回应可见动作
- 产出：`master.wav`

### 3.5 质检
- 干什么：抽帧看片、找问题、给证据
- 内功：证据契约（帧号 + 坐标 + 截图），没有证据不许说通过
- 检查项：字幕压脸、字号过小、黑帧、静音、音画偏移、时长、响度、缺字错字
- 错字不由质检「看」出来，由剪辑阶段的错字治理解决（热词注入 + 受约束纠错），质检只负责核对治理结果：改了几处、打回几处、还有几处没把握，全部带位置
- 产出：质检报告（可点开到具体帧）

### 3.6 运营
- 干什么：标题、发布文案、封面文案、排期、复盘
- 内功：三平台标题契约、数据回填、规则提炼
- 产出：发布文案 md、排期条目、风格卡更新

## 4. 一条片在群里怎么走

```
用户：新建项目群 → 群里自动有 制片人
用户：丢素材 +「按折光做个 60 秒的，发视频号」
制片人：一张确认卡（平台 / 时长 / 有没有稿子 / 禁用词）——一次问完
制片人：定 Goal，@选题 → @剪辑 → @包装 → @声音 → @质检 → @运营
各小 bot：在群里报进度、发中间产物；用户随时插话改
质检：@出问题（第 47 秒字幕压下巴，帧 1412，已避开）
定稿：制片人交付四件套（mp4 / srt / 封面 / 发布文案）
成片自动进媒体库，可排期、可回填数据
```

**改一句只重跑下游**：用户说「第三段删掉」，制片人转给剪辑，只改 timeline 的一个节点，只重渲那两段，包装缓存不动。

## 5. 两种形态

| 形态 | 给谁 | 形态 |
|---|---|---|
| 桌面应用 | 终端创作者 | Electron，内嵌 pinned DSH + 独立 DSH_HOME，双击即用，自带 ffmpeg / 字体 / 模型 |
| DSH 插件 | 已在用 DSH 的人 | 装进现有 DSH 侧栏，共用同一套代码 |

两者共用一份 `media/` 插件代码，`app/` 只是壳。与 DS-Bot 同构。

## 6. 编排外观（VisionQA 纪律）

- 左：bot 列表（按项目分组）
- 中：群聊流（进度、中间产物、@、确认卡）
- 右：可折叠项目面板（素材 / 时间线 / 成片 / 质检报告）

Token：底 `#101011`、表面 `#171718`、内嵌 `#202022`、描线 `#343436`、正文 `#f4f4f0`、次要 `#9f9fa3`、强调只有亮灰 `#d7d7d3`。

多 bot 不靠颜色区分：几何标记 + 字重 + 左侧 2px 竖条 + 名字前缀。状态用明度阶梯。唯一彩色是质检报告里的暗红。

## 7. 后台（不是主界面）

媒体库在后台：灵感、成片、排期、复盘、风格卡。群里的产物自动落进来。风格卡能回到 bot 的记忆里，形成闭环。

## 8. 什么是"效果足够好"

用户不看 skill，只看三件事：
1. 粗剪出来，删的是不是该删的
2. 包装出来，像不像折光那种质感
3. 质检过了，能不能直接发

这三件事由内功决定，不由界面决定。

## 9. P0 范围

- 制片人 + 剪辑 + 包装 + 质检（四个）
- 两条模板（PPT 底座、光轨），第三条排期
- 两条模板都出 3:4 与 9:16；画幅由平台默认、确认卡可改，换画幅不动时间线
- 群聊、确认卡、进度、中间产物预览
- 四件套交付
- 桌面应用形态

## 10. 未决

1. bot 包的分发单位（现在模板和 skill 都写死在仓库里）
2. 群聊成本策略（小模型调度 / 大模型只做关键判断）
3. 光轨的「字藏人物身后」在 Windows 上用什么做人物蒙版（上游依赖 macOS Vision）
4. 术语表谁来维护：现在只有仓库里一个 JSON，客户加自己的行业词要改文件。要不要做成群里的「术语」指令、甚至从成片里自动学
5. 数字写法要不要按模板统一（现在有意不动「三秒」「一个人」这类中文数字）
