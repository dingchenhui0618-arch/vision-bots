# 质检规矩（2026-11-23 重做）

> 起因：第一版真素材自测，质检报「6 项全过」，但成片里光轨横穿人脸、字幕把「一盆冷水」写成「一瓶冷水」、
> 「用 GDP」是「用 GPT」、还有一句「但是AI来去做内容」连着出现两遍。**那版质检等于没做。**
> 这一版的原则只有一句：**没有证据不许判通过，证不出来就判不通过。**

自检入口：`node scripts/check-qa.mjs`（18 条）。每条规矩都要能被一个具体坏例子打红。

## 现在的检查项

| id | 查什么 | 判据 | 证据 |
|---|---|---|---|
| duration | 成片时长与剪辑账对得上 | 只报数，不判 | 源时长、剪掉时长、段数 |
| target | 目标时长 | 差 > 12% 判不过 | 差额（秒） |
| silence | 长静音 | 存在 > 0.8s 静音判不过 | 静音区间 |
| loudness | 响度 | 不在 −22 … −8 LUFS 判不过 | 实测 LUFS |
| caption_coverage | 一个字都不许丢 | 有漏字判不过 | 原文字数 / 上屏字数 |
| caption_length | 单卡长度 | > 16 字判不过 | 最长卡字数 |
| caption_flow | 字幕流 | 相邻卡互压 > 0.05s 判不过；末尾空 > 2s 判不过 | 叠压的时间点 |
| duplicate_lines | 重复句 | 相邻两卡相似 ≥ 80% 判不过 | 时间点 + 原句 |
| asr_confidence | 错字治理的把握 | 低置信词占比 > 8%，或词数/时间码被动过，判不过 | 占比 + 具体词与时间点 |
| section_pace | 段落节奏 | 段数不在 4–14，或有段短于 3s，判不过 | 段数 + 每段时长 |
| layout_zone | 版式契约 | 大字/轨道/字幕进上 56%，或 HUD 出上 10%，判不过 | 每个盒子的顶边像素 |
| layout_overlap | 文字互压 | 同一帧两个盒子重叠 > 4px² 判不过 | 帧号 + 两个 tag |
| text_contrast | 文字读不读得出 | 大字/轨道 < 3:1，HUD/字幕 < 4.5:1 判不过 | 最差对比度 + 时间点 |
| safe_area | 出画/贴边 | 任一盒子距边 < 16px 判不过 | 盒子坐标 |
| subject_known | 人物位置 | 未接人物蒙版时如实标「未接入」，不算通过也不算失败 | 说明文字 |
| subject_clear | 文字压人 | 有头部实测时，文字进头部区间判不过 | 头部像素区间 |
| layout_conflict | 模板自报的几何冲突 | 渲染器说「让不开人」判不过 | 轨道 y |
| layout_evidence | 烧字幕路径 | 没有像素级盒子证据时如实列明（不计入不通过） | 引擎类型 |

## 两个关键机制

**1. 盒子（boxes）来自渲染器，不从模板文字里猜。**
film.js 在画每个元素时调 `reg()` 登记屏幕坐标，`--mode qa` 每 0.4 秒采一帧把盒子吐回来。
质检拿到的就是「这版画面把字画在哪」，不是「模板说有 pill 所以应该能读」。

**2. 对比度从成片真实像素里量。**
抽 24 帧成片（低分辨率），对每个盒子取区域，把接近文字颜色的像素当字、其余当底，算 WCAG 比。
顶部白字打在白色天花板上的那种问题，这一步一定打红——它量的就是最终画面。

## 已知缺口（写在明处）

- **语义级错字**（一盆→一瓶、一天→一千、GPT→GDP）：确定性检查查不出来。
  现在能拦住的是「重复句」和「低置信占比超线」；真要治得靠 ASR 提质 + 术语表，不是质检。
- **脸部位置**：还没有机器判定。目前靠版式契约（文字只在下半区）保证，人物蒙版接上之后
  由 alpha 轮廓换成真判定（见 [MATTE.md](MATTE.md)）。
- **审美**：质检只证「没坏」，不证「好看」。好看由模板和抽帧人工过。

## 语义层（2026-11-23 加）：数值查不出的错，由模型读全文来找

数值层能证明「有字幕、不重叠、对比度够、没重复卡」，证明不了「这句话说的是不是人话」。
真素材自测里 `花一千的时间`（应为「一天」）、`捡内容生产力才是网道`（应为「王道」）、
`GDP / Cloud`（应为 GPT / Claude）全部从数值层底下溜过去，旧版 6/6 是假通过。

现在质检最后一项 `semantic_review` 由模型审读交付字幕全文，**只加严、不放宽**：

- 只能新增失败项，删不掉任何代码检查。
- 每条问题必须给`quote`，逐字来自某张字幕卡或某段大字；对不上的直接丢弃（模型编的）。
- 同音错字必须过硬校验（字数不变 + 拼音一致），验不过的降级成「疑似」，只记录不拦。
- 读全性：模型要报字幕卡条数、第一张和最后一张卡的开头各 4 个字，对不上就不采信——
  只报条数没用，没读卡的模型也能数出来。
- **没跑成 = 不通过**：超时、空返回、读全性对不上，都判 `semantic_review` 失败并写清原因。
  数值层全过只能说「数值层过了、语义层没查」，不能算交付合格。

## 实现教训（这一轮踩的）

- **盒子必须和画出来的 pill 重合**。渲染器 `reg()` 报的盒子比实际 pill 宽 22px、高 16px，
  多出来的那一圈量的是背景（白天花板），对比度凭空掉到 2.12:1。现在 HUD 盒子 = pill 矩形本身。
- **量对比度的分辨率要够**。216×384 下 22px 的 HUD 只剩 4px，字和 pill 的边界被缩放糊掉，
  「非文字像素中位数」会把抗锯齿像素算成背景，同样量出假低值。改到 540×960（16 帧，约 25MB）。
- **标题模型算出来 ≠ 标题上了屏**。`validateBatch` 产出带 `ok:true`，`applyTitles` 却按 `source` 过滤，
  10 条模型标题一条没贴上，画面上全是原句——现在两边都按 `ok === true` 认，并有回归测试。
- **一句在屏幕上只该出现一次**：字幕和大字的去重以前按「一句包住另一句」判，
  否则 `AI模型做AI工具的` 和 `做AI工具的` 会同时压在画面上。
  但 2026-11-24 改成句级大字之后，大字本来就是字幕这一句的压缩词，**几乎总是字幕的子串**，
  再按“包含”判就会把正常句子的字幕整条吞掉。现在只认「完全一样」；两层各显示各的，
  这一条不变量由 `scripts/check-align.mjs` 钉住。
